Reading the ctags gaps (approximate, by design):
  - Go (A): ctags 'func' = 4529, identical to Nodes; the rest of its count is 2710 struct fields ('member') and 68 interface method specs.
  - JavaScript (A, D, E): ctags also tags nested functions, object-literal methods and named callbacks; Nodes units are top-level
    functions, class methods and functions assigned to names. Calls between them are name-match (confidence 0.3/0.5), never cross-language.
  - TypeScript (A): Nodes is higher (1626 vs 1496): arrow functions assigned to consts are units; ctags tags them as constants.
  - Python: the precise resolver skips functions nested in functions (ctags counts them): 0-7% gap; classes match except 2 of 181 in C.
cochg n/a: no file pair reaches support 2 (single-commit repos). A has one commit (a cache snapshot).

Bugs this test found and fixed before run 3 (run 2 output kept in runs/ingestion2.jsonl):
  - re-init was not idempotent on A/B/C (35/2/8 units): two symbols with the same name in one file (property setters,
    try/except fallbacks) shared a uid. Later duplicates are now Name@2, Name@3.
  - co-change support was higher than raw git on B/C: the 30-file cap counted only indexed files of a commit; it now uses the full commit size.
  - region ids based on line numbers renamed regions on unrelated edits (run 1): now ordinal (module@1, module@2...).
